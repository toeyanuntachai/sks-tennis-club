# ระบบ Ranking ของ SKS Tennis Club

สถานะ: ผู้ใช้ยืนยันแผนและรีวิวในเครื่องแล้ว อนุญาต deploy เมื่อ 6 ตุลาคม 2026 โดยคงเหรียญหลังชื่อตามอันดับร่วม

## ขอบเขตงาน

เพิ่มการบันทึกผลแมตช์เล่นคู่ ประวัติผล และตารางอันดับรายคนในเว็บเดิม รีวิวในเครื่องก่อนเผยแพร่ผ่าน main ที่เชื่อม Railway ตามการอนุญาตล่าสุดของผู้ใช้

แหล่งบริบท: แชต “วางแผนเว็บกลุ่มเทนนิส” (`01a0f66c-e43e-7520-afda-b3c0826401b5`) และคำถามเดิมใน `.scratch/tennis-club/issues/01-leaderboard-rules.md` กับ `02-recording-flow.md`

## กติกาที่ตกลงในแชตเดิม

- เน้นความสนุก เล่นคู่และสลับคู่บ่อย จัดอันดับรายคน
- ผลแมตช์รับ 4–0, 4–1, 4–2 หรือ 3–3 รวมถึงสกอร์กลับด้านของผลชนะ ผู้ใช้เพิ่มตัวเลือกแบบ 6 เกมเมื่อ 6 ตุลาคม 2026: ชนะ 6–0 ถึง 6–4 หรือเสมอ 5–5 รวมสกอร์กลับด้าน โดยยังรับแบบ 4 เกมเดิม
- ชนะ +3 เสมอ +1 แพ้ +0 ทั้งสองคนในทีมได้แต้มเท่ากัน
- สมาชิกคนใดก็บันทึกผลแทนได้ หนึ่งแมตช์ควรมีผลหนึ่งรายการ และแก้ผลผิดได้
- ตารางอันดับแสดงจำนวนแมตช์และเปอร์เซ็นต์ชนะประกอบ
- ระบบใช้ตัวตนสมาชิกผ่าน LINE อยู่แล้ว

กติกาเหล่านี้เป็นข้อตกลงสำหรับงานเพิ่มผลแมตช์และ Ranking ตามรายละเอียดด้านล่าง

## กติกาที่ผู้ใช้ยืนยันในรอบแรก

ผู้ใช้ตอบว่า “ตามแนะนำทั้งหมด” เมื่อ 6 ตุลาคม 2026:

1. รอบอันดับรายเดือน เริ่มแต้มใหม่และเก็บประวัติเดือนเก่า
2. แต้มเท่ากันเป็นอันดับร่วม เช่น 1, 1, 3 ไม่มีเกณฑ์รองตัดสินอันดับ เปอร์เซ็นต์ชนะ = ชนะ / แมตช์ทั้งหมด รวมเสมอในตัวหาร พร้อมแสดงชนะ–เสมอ–แพ้
3. แมตช์ต้องอยู่ภายในนัดที่เปิดไว้
4. ผู้เล่นในผลแมตช์ต้องเป็นสมาชิกที่มีบัญชี LINE ในเว็บ ชื่อที่ผู้จัดพิมพ์เพิ่มยังไม่รับแต้มจนกว่าจะผูกบัญชี

เหตุผลของแนวทางแต้มสะสมรายคนอยู่ใน [ADR 0001](adr/0001-personal-points-ranking.md)

## กติกาที่ผู้ใช้ยืนยันในรอบที่สอง

ผู้ใช้ตอบว่า “ตามแนะนำทั้งหมด” เมื่อ 6 ตุลาคม 2026:

5. ใช้วันของนัดตามเขตเวลา Asia/Bangkok จัดเข้ารอบเดือน กรอกได้ตั้งแต่เวลาเริ่มนัด และแก้ผลเดือนเก่าได้ อันดับเดือนนั้นคำนวณใหม่ตามผลที่ถูกต้อง
6. เลือกสมาชิกที่มีชื่อในนัดได้ รวมผู้ได้ที่ คิวสำรอง และคนถอนชื่อที่ได้เล่นจริง สมาชิกที่ยังไม่มีชื่อให้ผู้เปิดนัดเพิ่มก่อน ชื่อที่ผู้จัดพิมพ์เพิ่มต้องผูกบัญชีก่อนเลือกลงแมตช์
7. ผู้กรอกกับผู้เปิดนัดแก้ผู้เล่น สกอร์ หรือยกเลิกผลได้ แสดงผู้กรอกและผู้แก้ล่าสุด ผลที่ยกเลิกยังดูย้อนหลังได้แต่ไม่นับแต้มและสถิติ
8. การยกเลิกนัดเก็บผลที่เล่นจริงไว้ หากผลผิดให้ยกเลิกผลแยก ล็อกวันนัดเมื่อมีผลเพื่อไม่ให้แต้มย้ายเดือนโดยไม่ตั้งใจ
9. กดบันทึกซ้ำหรือส่งคำขอเดิมซ้ำไม่สร้างผลเพิ่ม เมื่อมีคู่และสกอร์เดียวกันในนัดให้เตือนและยืนยันว่าเป็นแมตช์ใหม่ได้ เพราะกลุ่มอาจเล่นซ้ำจริง
10. จัดอันดับเฉพาะสมาชิกที่มีผลที่ยังนับในเดือนนั้น คนแพ้ทุกแมตช์มี 0 แต้มและยังมีอันดับ คนไม่มีแมตช์แสดง “ยังไม่มีแมตช์เดือนนี้” ไม่จัดอันดับร่วมกับคนที่เล่นแล้ว

เหตุผลการเก็บผลแยกจากสถานะนัดและล็อกวันอยู่ใน [ADR 0002](adr/0002-match-history-and-event-date.md)

## จุดสุดท้ายสำหรับยืนยันพร้อมแผนรวม

ข้อ 11 ที่ยืนยันแล้ว: นัดที่ยกเลิกแล้วไม่รับผลแมตช์ใหม่ แต่ผู้กรอกกับผู้เปิดนัดยังแก้หรือยกเลิกผลเดิมตามสิทธิ์ได้ เพื่อเก็บผลที่เล่นจริงโดยไม่เปิดให้บันทึกการเล่นเพิ่มในนัดที่ปิดแล้ว

ไม่มีคำถามกติกาค้าง ผู้ใช้อนุญาต deploy และ push หลังรีวิวแล้ว

## ผลงานสำหรับรีวิวหลังยืนยันแผน

1. ในรายละเอียดนัด: ฟอร์มเลือกผู้เล่นสี่คน แบ่งสองทีม ค้นหาชื่อได้ และเลือกสกอร์ตามกติกา
2. ประวัติผลของนัด: แสดงทีม สกอร์ ผู้กรอก ผู้แก้ล่าสุด และคำสั่งแก้หรือยกเลิกตามสิทธิ์ พร้อมคำเตือนเมื่อมีผลคล้ายรายการเดิม
3. หน้า Ranking: เลือกเดือน ดูอันดับร่วม แต้ม จำนวนแมตช์ ชนะ–เสมอ–แพ้ และเปอร์เซ็นต์ชนะ พร้อมสถานะของตัวเองเมื่อยังไม่มีแมตช์ เหรียญ 🥇 🥈 🥉 อยู่หลังชื่อและอิงอันดับจริง รวมอันดับร่วม

ใช้ React, shadcn และระบบสมาชิก/API/SQLite เดิม ไม่เพิ่มระบบจัดอันดับฝีมือ สถิติคู่หู คู่ปรับ หรือการแชร์ผลในงานรอบนี้ ส่งลิงก์รีวิวในเครื่องพร้อมข้อมูลตัวอย่างที่แยกจากฐานข้อมูลจริง เก็บการแก้ไฟล์เดิมของผู้ใช้ไว้

## เกณฑ์ตรวจสอบ

- ผลชนะ เสมอ และแพ้ให้แต้มทั้งสี่คนถูกต้อง
- ไม่รับผู้เล่นซ้ำในแมตช์เดียวหรือสกอร์ที่อยู่นอกกติกา
- ผลยึดเดือนของวันนัดตามเวลาไทย รวมกรณีกรอกย้อนหลังและขอบเขตเปลี่ยนเดือน
- การแก้ผู้เล่นหรือสกอร์ และการยกเลิกผลคำนวณแต้มกับสถิติใหม่ถูกต้อง รวมเดือนเก่า
- อันดับร่วมเป็น 1, 1, 3 และเปอร์เซ็นต์ชนะรวมแมตช์เสมอในตัวหาร
- คนเล่นแล้วแต่มี 0 แต้มยังมีอันดับ คนไม่มีผลที่นับไม่ติดอันดับ
- ตรวจสิทธิ์ผู้กรอก ผู้เปิดนัด และสมาชิกอื่น รวมรายชื่อผู้เล่นและบัญชีที่เลือกได้
- กดซ้ำ ส่งคำขอเดิมซ้ำ และแมตช์ใหม่ที่ผู้เล่น/สกอร์เดิมไม่ทำให้แต้มซ้ำหรือหาย
- วันนัดที่มีผลถูกล็อก การยกเลิกนัดไม่ลบแต้ม และการยกเลิกผลไม่นำผลนั้นมานับ
- ข้อมูลผลยังอยู่เมื่อเปิดฐานข้อมูลอีกครั้ง และ migration ไม่ทำให้ข้อมูลเดิมหาย
- ตรวจฟอร์มบนมือถือ คีย์บอร์ด และการเก็บค่าที่กรอกเมื่อบันทึกไม่สำเร็จ
- ระบบนัด รายชื่อ คิว และสถานะจ่ายเดิมยังทำงานตามเดิม

## สถานะการตรวจ

สร้างฟีเจอร์ตามแผนแล้ว Build/TypeScript และชุดทดสอบ API กับหน้าเว็บผ่าน รวมการสำรอง migration ข้อมูลเดิม ผลทุกสกอร์ อันดับร่วม เขตเวลาไทย การแก้ผู้เล่น/ผลเดือนเก่า การยกเลิกผล สิทธิ์ คำขอซ้ำ การเปิดฐานข้อมูลอีกครั้ง และการเก็บแบบร่างเมื่อล้มเหลว

เว็บรีวิวใช้ `scripts/review-ranking.mjs` เปิดบน 127.0.0.1:4399 พร้อมข้อมูลตัวอย่างในฐานข้อมูลชั่วคราว ไม่เชื่อม LINE หรือฐานข้อมูลใช้งานจริง แยกจากรุ่นที่จะ deploy

ตรวจหน้าจอจริงที่ความกว้าง 390 พิกเซลแล้ว: ค้นหาและเลือกสี่คน บันทึกผล ยกเลิกผลโดยเก็บประวัติ และดูอันดับเดือนเก่าทำงานได้ ไม่พบข้อผิดพลาดใน browser console ชุดทดสอบสุดท้ายผ่าน 23 รายการ (server 5 และ UI 18) พร้อม Build/TypeScript และ diff check ผู้ใช้รีวิวแล้วและอนุญาตเผยแพร่
